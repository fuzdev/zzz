markdown_links.ts

Links and headings in rendered markdown, for MarkdownPreview and the markdown view's drawer — pure functions over mdz's parsed nodes, with no app state, plus the one DOM query matching links to their rendered anchors.

A link in a file resolves against the file's path, the way a repository host reads it: ./x.md, ../y/z.md, and x.md against the file's directory, and a root-relative /docs/x.md against the root of the open directory holding the file (the workspace, which is usually the repository). Whether the result exists is the file index's call (MarkdownLinkIndex), and what the index can't see is unknown, never broken.

MarkdownLinkStatus
#

markdown_links.ts view source

MarkdownLinkStatus

type "file" | "directory" | "broken" | "outside" | "skipped" | "root_relative"

import type {MarkdownLinkStatus} from '@fuzdev/zzz/markdown_links.js';

How a path link stands against the file index:

  • file / directory — it names an indexed file, or a folder holding one
  • broken — it's inside a root the index covers, where the index would list it, yet nothing is there
  • the index can't say (see MarkdownLinkMark's unknown):
    • outside — outside every root the index covers
    • skipped — inside a folder the index never enters (FILE_INDEX_IGNORED_DIR_NAMES)
    • root_relative — written /… and not found from the workspace's root, which may not be the repository's

MarkdownLinkTarget
#

markdown_links.ts view source

MarkdownLinkTarget

type { kind: "external"; href: string; } | { kind: "fragment"; fragment: string; } | { kind: "path"; path: string; directory: boolean; fragment: string | null; root_relative: boolean; } | { kind: "inert"; }

import type {MarkdownLinkTarget} from '@fuzdev/zzz/markdown_links.js';

Where a link in a markdown file leads:

  • external — an http: or https: URL, left to the browser
  • fragment — a heading in the same document (#id, decoded)
  • path — an absolute path on disk, with directory when the link names a folder (a trailing /, or a last segment of . or ..), its decoded #fragment if any, and root_relative when it was written /…
  • inert — nothing to follow: empty, query-only, another scheme, protocol-relative, malformed, climbing past its root, or relative with no file to resolve against

query_markdown_link_anchors
#

markdown_links.ts view source

(container: ParentNode, links: readonly MarkdownLink[]): HTMLAnchorElement[] | null import {query_markdown_link_anchors} from '@fuzdev/zzz/markdown_links.js';

The rendered <a> of each of links inside container, matched by document order — the ith anchor with an href is the ith link — or null when the counts disagree, so no link is paired with another's anchor. Order, not href, because the href isn't always the reference: mdz renders a root-relative one through SvelteKit's resolve, collapsing its leading run of / and \ to one / (//a/b.md renders /a/b.md), so an anchor that reads as a path can stand for a reference this module reads as protocol-relative or backslashed, and inert. Assumes mdz renders every anchor in container, which holds while no mdz context injects components that render their own.

resolve_markdown_link
#

markdown_links.ts view source

(href: string, options?: ResolveMarkdownLinkOptions): MarkdownLinkTarget import {resolve_markdown_link} from '@fuzdev/zzz/markdown_links.js';

Resolves href, a link's reference in a markdown file, to where it leads (see MarkdownLinkTarget). A path link drops its ?query, keeps its #fragment, has each segment percent-decoded, and is normalized: . and empty segments vanish and .. climbs, but never above / — or above root_dir for a root-relative link — which makes it inert. An escape that decodes to / or a NUL is inert too, since it would change the path's shape.
