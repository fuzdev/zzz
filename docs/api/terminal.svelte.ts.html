terminal.svelte.ts view source

import {Terminal} from '@fuzdev/zzz/terminal.svelte.js';

A PTY terminal run: the command it runs, its backend process status, a bounded output buffer that outlives any mounted view, and ordered input.

Output is acked to the backend (terminal_ack) as it's consumed, which is what paces a process that prints faster than this client takes it: with views attached, once every view has consumed a chunk; with none, as soon as it's buffered (the buffer drops its oldest output, so it never backs up).

Input goes through a per-terminal queue with at most one terminal_data_send in flight — the backend dispatches one socket's requests concurrently, so independent sends could reorder keystrokes. Data queued while a send is in flight is coalesced into the next send. Resizes coalesce to the latest size.

Forwards new output to listener until detached, and returns the output buffered so far for the caller to replay first. send_input

Queues data as input, sent in order with at most one terminal_data_send in flight. Input queued while starting is sent once the process starts.

On queue_overflow (the child isn't reading its input) the data is retried with backoff — the backend enqueued none of it, so a resend can't duplicate — and the error is surfaced until a send succeeds. On not_found the backend no longer has the process, so the terminal is marked lost. Any other failure is surfaced without a retry, because the data may have been delivered.

Closes the running process with terminal_close. The backend broadcasts no terminal_exited for a closed terminal, so the response settles the status — unless a natural exit was recorded first. A not_found means the process is already gone (it just ended, or zzzd restarted), which is what closing wanted, so it closes with an unknown exit code and no error.

import {TerminalStatus} from '@fuzdev/zzz/terminal.svelte.js';

Lifecycle of a terminal's backend process:

  • starting — terminal_create is in flight
  • running — the PTY process is live
  • exited — the process exited on its own (terminal_exited), exit_code is its real code
  • closed — the user closed it (terminal_close), exit_code is the code the close observed, or null if the process outlived the close grace (the backend reaps it and broadcasts no terminal_exited)
  • failed — terminal_create failed, see error_message
  • lost — the backend no longer has the process: zzzd restarted, or it ended or was closed elsewhere while this client wasn't listening; see error_message
